# 학습 자료 페이지 제작 가이드라인

> Claude Code에게: 이 문서는 `요약노트_JSON.json`(이하 "JSON")을 기반으로 **9급 공무원 시험 학습 자료 웹 페이지**를 만들기 위한 가이드라인입니다. JSON과 이 문서를 함께 읽고, 명세를 그대로 따라 구현해 주세요.

---

## 0. 프로젝트 개요

### 0-1. 목적
사용자가 9급 공무원 시험을 위해 만들어진 **빈출 개념 요약 노트(JSON)**를 학습 자료 페이지로 열람·활용할 수 있게 한다. 기존 문제풀이 웹앱과 별도의 학습 모듈로 동작한다.

### 0-2. 기술 스택 (기존 문제풀이 웹앱과 통일)
- **백엔드**: FastAPI (Python 3.12) + SQLite
- **프론트엔드**: React + Vite (JSX, JavaScript - TypeScript 아님)
- **스타일**: Tailwind CSS 추천 (또는 기존 프로젝트와 동일한 스타일링 도구 사용)
- **DB 활용**: 진도 체크·북마크 데이터는 SQLite에 저장

### 0-3. JSON 데이터 위치
- 백엔드: `backend/data/요약노트_JSON.json` (FastAPI가 파일 로드 후 API로 제공)
- 프론트엔드는 직접 JSON을 import하지 않고 **반드시 백엔드 API를 통해** 데이터를 받아온다.

## 1. JSON 스키마 이해

JSON의 최상위 키 구조는 다음과 같다.

```json
{
  "meta": { ... },                    // 노트 메타정보
  "paradigm_shift": { ... },          // 2025년 대전환 섹션
  "top_10_areas": [ ... ],            // 빈출 TOP 10 (학습 우선순위)
  "area_details": { ... },            // 영역별 상세 정보
  "korean_grammar_basics": { ... },   // 한국어 문법 기초
  "top_15_traps": [ ... ],            // 함정 TOP 15
  "exam_round_mapping": { ... },      // 영역별 회차 매핑
  "study_priority_guide": { ... },    // 학습 우선순위 가이드
  "final_checklist": { ... },         // 시험 직전 체크리스트
  "final_motto": "..."                // 최종 한 줄 요약
}
```

### 1-1. `meta` — 노트 메타정보
```
meta.title           // "9급 공무원 국어 빈출 개념 요약 노트"
meta.subject         // "국어"
meta.grade           // "9급"
meta.analysis_scope  // "2022~2026 국가직 + 2022~2025 지방직 (총 9회차, 180문제)"
meta.version         // "1.0"
meta.purpose         // 노트 제작 목적
```
→ 대시보드 상단 헤더에 표시.

### 1-2. `paradigm_shift` — 2025년 대전환
```
paradigm_shift.title              // "2025년 대전환의 본질"
paradigm_shift.description        // 짧은 본문
paradigm_shift.disappeared_areas  // 사라진 영역 배열 [ {area, prev_frequency, current_frequency, study_priority} ]
paradigm_shift.increased_areas    // 급증한 영역 배열 (같은 구조)
```
→ 대시보드 최상단 배너 및 별도 페이지.

### 1-3. `top_10_areas` — 빈출 TOP 10
```
[
  {
    "rank": 1,
    "name": "비문학 추론",
    "frequency_per_round": "5~7문제",
    "difficulty": "상",
    "study_weight": 25
  },
  ...
]
```
→ 대시보드의 메인 카드 그리드. `study_weight`로 시각적 가중치 표현 가능.

### 1-4. `area_details` — 영역별 상세
객체이며 키는 영문 식별자 (예: `public_document_correction`, `outline_writing`, `logical_reasoning` 등). 각 영역마다 구조가 약간씩 다르므로 **유연하게 렌더링**해야 한다.

공통 필드:
- `name`: 영역 한글명
- `出題_position`: 출제 위치/빈도
- `format`: 출제 형식
- `related_questions`: 관련 기출 (문자열 배열)

영역별 고유 필드 예시:
- `core_rules`: 규칙 배열 (각각 rule, examples 또는 description 포함)
- `tools`: 풀이 도구 배열
- `traps`: 함정 배열
- `solving_steps`: 풀이 단계 배열
- `principles`: 풀이 원칙 배열
- `subcategories`: 하위 카테고리 (문법 영역 등)

⚠️ **주의**: `area_details`의 키 중 일부는 한자(出題)나 영문 혼합이다. JSON 키를 그대로 사용하되, UI에는 `name` 필드의 한글 이름을 노출한다.

### 1-5. `korean_grammar_basics` — 한국어 문법 기초
```
korean_grammar_basics.antonyms          // 방향 반의어 3가지
korean_grammar_basics.causative_passive // 사동/피동
korean_grammar_basics.honorifics        // 높임법 3가지
korean_grammar_basics.tense_modality    // 시제 형태소 양태 기능
```
→ "문법 기초" 별도 페이지.

### 1-6. `top_15_traps` — 함정 TOP 15
```
[
  { "rank": 1, "trap": "...", "frequency": "매우 높음", "countermeasure": "..." },
  ...
]
```
→ "함정 모음" 페이지에서 카드 그리드로.

### 1-7. `exam_round_mapping` — 영역별 회차 매핑
```
exam_round_mapping.description
exam_round_mapping.mapping = {
  "공문서_수정": { "2025_국가직": [1], "2026_국가직": [1], "2025_지방직": [1] },
  "비문학_추론": { "2022_국가직": [9, 10, 11, 12, 13, 20], ... },
  ...
}
```
→ "회차 매핑" 검색 페이지. 필터링 가능해야 함.

### 1-8. `study_priority_guide` — 학습 우선순위
```
study_priority_guide.title
study_priority_guide.absolutely_required  // [ {area, expected_questions, priority} ]
study_priority_guide.do_not_study         // 학습하지 말아야 할 영역 (문자열 배열)
study_priority_guide.total_target_questions
```

### 1-9. `final_checklist` — 시험 직전 체크리스트
```
final_checklist.one_week_before    // 1주 전 체크 항목 (문자열 배열)
final_checklist.day_before = {
  must_remember: [ ... ],
  exam_strategy: [ ... ]
}
```
→ 인터랙티브 체크박스 페이지. 사용자가 체크하면 SQLite에 저장.

### 1-10. `final_motto`
짧은 슬로건. 푸터 또는 메인 페이지 강조 영역에 표시.

## 2. 페이지 구조 및 라우팅

### 2-1. 페이지 목록 및 URL

| 경로 | 페이지 | 주요 데이터 소스 |
|------|--------|------------------|
| `/` | 대시보드 (홈) | `meta`, `paradigm_shift`, `top_10_areas`, `final_motto` |
| `/areas` | 영역별 학습 목록 | `top_10_areas`, `area_details` (목록만) |
| `/areas/:areaKey` | 영역별 상세 | `area_details[areaKey]` |
| `/traps` | 함정 모음 | `top_15_traps` |
| `/grammar` | 문법 기초 | `korean_grammar_basics` |
| `/exam-mapping` | 회차 매핑 검색 | `exam_round_mapping` |
| `/priority` | 학습 우선순위 가이드 | `study_priority_guide` |
| `/checklist` | 시험 직전 체크리스트 | `final_checklist` (+ DB) |
| `/search` | 통합 검색 결과 | 전체 JSON |
| `/bookmarks` | 북마크 모음 | DB |

### 2-2. 공통 레이아웃

- **상단 헤더**: 사이트 타이틀(`meta.title`), 검색창, 다크모드 토글, 북마크 페이지 링크
- **좌측 사이드바**(데스크탑) 또는 **상단 네비게이션**(모바일): 페이지 목록
- **하단 푸터**: `final_motto` + `meta.analysis_scope`

## 3. 페이지별 상세 명세

### 3-1. 대시보드 `/`

**구성 요소(위→아래 순서):**

1. **헤더 배너** — `paradigm_shift.title` + `description`을 강조해서 표시. 배경색은 강조 색 (예: 파란 그라데이션).
2. **빈출 TOP 10 카드 그리드** — `top_10_areas`를 순위 순으로 표시. 카드 클릭 시 `/areas/:areaKey`로 이동.
   - 카드에 표시할 정보: rank, name, frequency_per_round, difficulty
   - `study_weight`를 카드 크기나 진하기에 반영 (예: weight 25는 큰 카드, weight 3은 작은 카드)
   - 난이도별 색상: 상=빨강, 중=노랑, 하=초록
3. **사라진 영역 vs 급증 영역 비교 표** — `paradigm_shift.disappeared_areas`와 `increased_areas`를 좌우 또는 위아래로 나란히 표시.
4. **학습 진도 요약** — DB에서 사용자의 진도(체크리스트 완료율, 북마크 수 등) 가져와 표시.
5. **최종 한 줄 요약** — `final_motto` 강조 텍스트.

### 3-2. 영역별 학습 목록 `/areas`

- `top_10_areas`를 표 또는 리스트로 표시
- 각 항목에 `area_details`에 대응하는 키가 있으면 "상세 보기" 버튼 추가 (없으면 비활성화)
- 진도 체크 표시 (`/areas/:areaKey` 페이지를 한 번이라도 열었는지 DB에서 확인)

⚠️ `top_10_areas[i].name`을 `area_details`의 키로 매핑할 때 주의: 키가 영문이므로 매핑 테이블이 필요할 수 있다. 매핑 예:
- "비문학 추론" → `nonfiction_inference`
- "논리 추론 (참/거짓·명제)" → `logical_reasoning`
- "공문서 수정·개요 작성" → `public_document_correction` + `outline_writing` (2개 묶음)
- "강화/약화 평가" → `strengthen_weaken`
- "글의 흐름 배열" → `passage_ordering`
- "문맥상 어색한 부분 수정" → `awkward_revision`
- "대화·견해 분석" → `dialogue_analysis`
- "어휘 바꿔쓰기" → `vocabulary_substitution`
- "문법 (활용·발음·형태소)" → `grammar`
- "지시 대상 식별" → (별도 키 없음, 공통지문 일부)

이 매핑은 **백엔드에서 처리**하여 API 응답에 `areaKey`를 함께 내려주는 것을 권장.

### 3-3. 영역별 상세 `/areas/:areaKey`

**구성 요소:**

1. **헤더**: `name`, `出題_position`, `format`, 진도 체크/북마크 토글 버튼
2. **출제 형식 섹션**: `format`을 큰 박스로 표시
3. **핵심 규칙/원칙 섹션**: 
   - `core_rules`, `principles`, `tools`, `solving_steps`, `core_principles` 중 존재하는 것을 모두 렌더링
   - 각 항목은 expand/collapse 가능한 아코디언으로
   - 예시(`examples`)가 있으면 들여쓰기해서 표시 (특히 잘못된 예 → 올바른 예 비교)
4. **함정 섹션**: `traps`가 있으면 빨간색 박스로 강조 표시
5. **하위 카테고리 섹션** (`subcategories`가 있는 문법 영역): 탭 또는 아코디언으로 분할
6. **관련 기출 섹션**: `related_questions` 배열을 칩(chip) 형태로. 클릭 시 회차 매핑 페이지에 자동 필터 적용된 상태로 이동.

⚠️ **유연한 렌더링이 핵심**: 영역마다 필드 구성이 다르므로, **존재하지 않는 필드는 그냥 스킵**하는 안전한 렌더링 로직을 구현하라.

### 3-4. 함정 모음 `/traps`

- `top_15_traps`를 카드 그리드로
- 각 카드: rank, trap, frequency, countermeasure
- `frequency` 값에 따라 색상 구분: "매우 높음"=빨강, "높음"=주황, "중간"=노랑
- 카드 클릭 시 펼침 애니메이션으로 countermeasure 상세 표시
- 검색 기능 (trap 텍스트로 필터링)
- 빈도순/순위순 정렬 토글

### 3-5. 문법 기초 `/grammar`

- 4개 하위 섹션 탭으로 구성: 반의어 / 사동·피동 / 높임법 / 시제·양태
- 각 섹션은 `korean_grammar_basics` 내 해당 키의 내용을 표 또는 카드로 표시
- 예시(`examples`)를 강조 표시

### 3-6. 회차 매핑 검색 `/exam-mapping`

- 좌측: 필터 패널
  - 영역 선택 (다중 선택 가능): `exam_round_mapping.mapping`의 키들
  - 회차 선택: 2022~2026 국가직/지방직 (체크박스)
- 우측: 매칭되는 영역-회차-문제번호 결과 테이블
- 예: "비문학_추론" + "2022_국가직" 선택 시 → [9, 10, 11, 12, 13, 20] 문제 번호 표시
- 검색창: 영역명으로 즉시 필터링

⚠️ JSON의 키 이름이 한국어이고 언더스코어가 포함되어 있다(`공문서_수정`). UI 표시 시 언더스코어를 공백으로 치환(`공문서 수정`).

### 3-7. 학습 우선순위 가이드 `/priority`

- 상단: `study_priority_guide.title`과 `total_target_questions` 강조
- "반드시 학습할 영역" 표: `absolutely_required` 배열을 표로 (area, expected_questions, priority 컬럼)
- "학습하지 말 영역" 박스: `do_not_study` 배열을 빨간 X 아이콘과 함께 리스트로

### 3-8. 시험 직전 체크리스트 `/checklist`

- 두 개의 섹션: "1주 전" / "전날"
- "전날" 섹션은 다시 "절대 잊지 말 것" + "시험 전략" 두 그룹으로
- 각 항목은 인터랙티브 체크박스
- 체크 상태는 SQLite의 `checklist_progress` 테이블에 저장
- 진행률 게이지 바 표시 (총 항목 중 체크된 비율)
- "모두 초기화" 버튼

### 3-9. 통합 검색 `/search`

- 검색창에 키워드 입력 → JSON 전체에서 해당 키워드 포함된 항목 찾기
- 결과는 출처별로 그룹화 (영역 상세 / 함정 / 회차 매핑 / 체크리스트 등)
- 각 결과는 클릭 시 해당 페이지로 이동
- 백엔드에 `/api/search?q=...` 엔드포인트 구현

### 3-10. 북마크 모음 `/bookmarks`

- 사용자가 북마크한 영역/함정 목록 표시
- DB의 `bookmarks` 테이블 활용

## 4. 백엔드 API 명세

### 4-1. 데이터 조회 API (JSON 기반)

```
GET  /api/meta
GET  /api/paradigm-shift
GET  /api/top-areas               // top_10_areas + areaKey 매핑 포함
GET  /api/areas                   // area_details 키 목록
GET  /api/areas/:areaKey          // 특정 영역 상세
GET  /api/grammar                 // korean_grammar_basics
GET  /api/traps                   // top_15_traps
GET  /api/exam-mapping            // exam_round_mapping
GET  /api/priority                // study_priority_guide
GET  /api/checklist               // final_checklist (사용자 진행 상태 병합)
GET  /api/search?q=keyword        // 통합 검색
```

### 4-2. 사용자 상태 API (DB 기반)

```
GET    /api/progress              // 영역별 열람 여부, 체크리스트 진행률
POST   /api/progress/area/:areaKey/view   // 영역 열람 기록
POST   /api/progress/checklist    // 체크리스트 항목 토글 { item_id, checked }
POST   /api/bookmarks             // 북마크 추가 { type, key }
DELETE /api/bookmarks/:id         // 북마크 삭제
GET    /api/bookmarks             // 북마크 목록
```

### 4-3. JSON 로딩 전략

- FastAPI 앱 시작 시 JSON을 메모리에 한 번 로드 (앱 라이프사이클)
- JSON은 정적 데이터이므로 매번 디스크 읽기 불필요
- 단, 향후 다른 과목 JSON도 추가될 수 있으므로 `data/` 폴더 스캔 로직 권장

```python
# 의사 코드
from fastapi import FastAPI
import json
from pathlib import Path

app = FastAPI()
DATA_DIR = Path("data")
notes_cache = {}

@app.on_event("startup")
```

### 8-2. 검색 구현 방식

```python
# 백엔드 의사 코드
def search_in_notes(notes, keyword):
    results = []
    keyword_lower = keyword.lower()
    
    def search_recursive(obj, path=[]):
        if isinstance(obj, dict):
            for k, v in obj.items():
                search_recursive(v, path + [k])
        elif isinstance(obj, list):
            for i, item in enumerate(obj):
                search_recursive(item, path + [str(i)])
        elif isinstance(obj, str) and keyword_lower in obj.lower():
            results.append({
                "path": ".".join(path),
                "snippet": obj[:200],
                "category": determine_category(path[0])
            })
    
    search_recursive(notes)
    return results
```
